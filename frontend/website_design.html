NeuroADHD Research Workbench: Complete Website Design

This document provides the formal architectural, human-computer interaction (HCI), and visual design specification for the NeuroADHD Research Workbench. The web interface serves as the primary visual telemetry, dataset ingestion, and quality-control hub for the 23-stage raw resting-state fMRI preprocessing pipeline, bridging low-level neuroimaging computation with clinical and research auditability.

1. Executive Summary & Design Philosophy

SECTION 01 / SPEC

1.1 Purpose of the Web Interface

Neuroimaging workflows often suffer from "black box" syndrome, where researchers execute command-line scripts without real-time visibility into intermediate registrations, boundary clipping risks, or quality-control failures. The NeuroADHD website was designed as a local single-page research application (SPA) running on http://127.0.0.1:8765 with four foundational objectives:

  • Real-Time Pipeline Telemetry: Providing volume-by-volume and stage-by-stage visual tracking across all 23 pipeline stages.
  • Fail-Closed Safety Transparency: Exposing the cryptographic research authorization gate directly in the UI, ensuring real participant scans are never processed prematurely.
  • Diagnostic Diagnostic Overlays: Providing high-contrast orthographic slice viewers for immediate visual validation of anatomical defacing, tissue segmentation, and SyN normalization.
  • Interactive Connectivity Inspection: Rendering 19,900 Fisher-$z$ CC200 correlation features directly on an interactive GPU-accelerated HTML5 canvas.
REGULATORY DESIGN INVARIANT: RESEARCH USE ONLY The UI design strictly prohibits diagnostic claim language (such as "Patient Diagnosed", "Disease Severity", or "Clinical Action Plan"). All model prediction surfaces are explicitly badged as Exploratory Research Pattern Classifier with visible probability gauges and fail-safe notices.

4. Research Authorization & Fail-Closed Governance UI

SECTION 04 / GOVERNANCE UX

4.1 Two-Phase Evidence-to-Runtime Activation Pattern

A cornerstone of the NeuroADHD website design is Fail-Closed Safety Transparency. Rather than hiding compliance checks in backend logs, the web interface places the Research Authorization Gate as a prominent, primary panel immediately beneath the KPI counters.

The interface implements a strict two-phase status visualization:

  • Phase A (Evidence Readiness Engine): Evaluates 14 genuine human documentary criteria across Institutional Sign-off, DHR NECRBHR-registered IEC approval/exemption, executed ADHD-200 DUA, DPDP Act 2023 / Rules 2025 compliance memo, and participant-scoped authorization. The UI reflects states: PENDING_EVIDENCE → READY_FOR_AUTHORIZATION_REVIEW. Crucially, the UI clearly communicates that reaching review readiness never unlocks execution.
  • Phase B (Cryptographic Runtime Gate): Verifies the canonical HMAC-SHA256 signature in configs/research_authorization_register.json. Until all 23 items are promoted to APPROVED with genuine evidence digests, the UI displays a glowing amber badge: REAL DATA PROCESSING LOCKED (23 requirements pending).
UI SAFETY RULE: PREVENTING AUTOMATED APPROVAL CLAIMS The frontend code is strictly read-only regarding authorization. There is zero UI capability or API endpoint to "click to approve" or bypass gates. Genuine human authorization requires external cryptographic key configuration and manual register signing.

6. Safe Data Intake & External Storage Boundary

SECTION 06 / INTAKE ARCHITECTURE

6.1 The 3-Path Upload Architecture

The website provides 3 distinct dropboxes for clinical and research intake, each tailored to specific hospital export formats:

  • Option 1 (Complete Session ZIP): Recommended. Accepts a pre-structured BIDS archive containing paired 3D T1w and 4D BOLD scans, validates sidecar JSONs, and checks $T \ge 50$ volumes and valid $TR$.
  • Option 2 (Individual NIfTI / DICOM Files): For staging individual modalities; includes automated series inspection and metadata sanitization.
  • Option 3 (Radiology Reports PDF/OCR): Accepts clinical radiology reports, routing them through local text/OCR extraction without mixing text with MRI image arrays.
DATA ISOLATION INVARIANT: EXTERNAL ROOT STORAGE To protect git repositories from multi-gigabyte binary bloat and prevent accidental data leakage, all uploaded ZIPs, staged DICOMs, converted BIDS sets, and conversion logs are saved exclusively outside the code tree in NEUROADHD_DATA_ROOT (default: ~/NeuroADHD_Data).
