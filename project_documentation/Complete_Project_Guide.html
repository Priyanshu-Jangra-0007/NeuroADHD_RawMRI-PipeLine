STEP 1: Project Introduction

1.1 What This Project Does

The NeuroADHD project is an automated neuroimaging preprocessing and feature extraction system. It ingests raw brain MRI scans (specifically 4D resting-state functional MRI scans and 3D anatomical structural scans), performs standardized medical image cleaning and spatial alignment, extracts regional neural signals from 200 distinct brain regions using the Craddock CC200 atlas, calculates pairwise functional connectivity (the strength of communication between brain regions), and feeds these connectivity values into a trained machine-learning model to predict ADHD-versus-neurotypical brain patterns for research.

1.2 Why This Project is Needed & The Problem it Solves

In historical research, machine-learning models were trained on pre-extracted tables of regional brain signals. However, raw MRI data coming directly from a hospital scanner (e.g., Siemens, GE, or Philips) cannot be fed into a machine-learning algorithm directly:

  • Head Motion: Patients naturally move their heads by fractions of a millimeter inside the scanner, corrupting functional measurements.
  • Anatomical Variation: Every human brain has a unique shape and size; brains must be mapped onto a standardized coordinate grid (the MNI152 template) so that region #45 in Patient A corresponds to region #45 in Patient B.
  • Physiological Noise: Heartbeats, breathing, and scanner magnetic field drifts create false signals that can drown out genuine neural activity.

The Solution: NeuroADHD provides an automated, standardized, reproducible 22-stage pipeline that handles raw scan intake, raw-BOLD motion estimation, metadata-driven slice-timing correction (DEC-STC-01), B0 susceptibility distortion correction (DEC-SDC-02), skull stripping, tissue segmentation, single-step composed spatial normalization, and nuisance regression, outputting standardized roi_CC200.csv tables and 19,900 Fisher-$z$ connectivity features without requiring manual neuroimaging software intervention.

1.3 Who Will Use It?

  • Neuroscience Researchers: Investigating functional brain connectivity alterations in neurodevelopmental conditions.
  • Biomedical Engineers & Data Scientists: Developing and validating computer-aided diagnostic algorithms.
  • Clinical Research Investigators: Evaluating prospective MRI cohorts in controlled academic studies.
IMPORTANT REGULATORY & MEDICAL DISCLAIMER
RESEARCH PROTOTYPE ONLY — NOT FOR CLINICAL DIAGNOSIS. ADHD is a psychiatric and behavioral neurodevelopmental condition diagnosed exclusively by certified clinicians through behavioral histories and DSM-5/ICD-11 criteria. This software must NEVER be used to diagnose, triage, or select treatments for patients. Real-scan preprocessing is locked behind a research authorization gate; all default runs execute in STRICTLY_SYNTHETIC_ONLY mode.

1.4 Plain-English Glossary of Technical Terms

TermSimple Plain-English Definition
fMRI (Functional MRI)An MRI technique that measures tiny blood-oxygen changes in the brain over time, showing which brain areas are active while a person rests.
BOLD Signal"Blood-Oxygen-Level-Dependent" signal. When neurons become active, they consume oxygen; BOLD measures this oxygen change.
T1-weighted MRI (T1w)A high-resolution, static 3D anatomical photograph of the brain's physical structure, showing sharp boundaries between grey and white matter.
VoxelA "3D pixel" inside an MRI scan. Just like a digital photo is made of 2D pixels, a 3D brain scan is made of millions of tiny cubes called voxels.

Fisher z-TransformationA mathematical formula ($z = arctanh(r)$) that converts correlation values into normally distributed values suitable for machine learning.
FrontendThe user interface (webpage) you see in your browser with buttons, tables, and graphs.
BackendThe Python server running in the background that receives files, executes mathematics, and returns results.
API"Application Programming Interface" — the standardized communication bridge between the frontend and the backend.

STEP 2: Initial Setup (Starting From Zero)

2.2 Step-by-Step Installation Commands

Command 1: Navigate to the Project Root

cd "<your-project-folder>"

Where to execute: In your operating system Terminal.
What it does: Changes your active directory into the project root folder.
Successful execution looks like: Your terminal prompt displays the folder path without returning any error.

Command 2: Activate the Virtual Environment

source .venv/bin/activate

Where to execute: In the project root.
What it does: Activates the isolated Python virtual environment containing all pre-installed scientific packages (DIPY, Nilearn, NiBabel, Scikit-Learn, SciPy, NumPy, Pandas, Matplotlib).
Successful execution looks like: Your command line prompt is prefixed with (.venv).

Command 3: Install Pinned Dependencies (Fresh Setup Only)

If you are setting up on a completely new machine where .venv does not exist, create it and install pinned packages:

python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements-lock.txt

What it does: Installs the exact locked versions of the 35 required scientific libraries so that there are zero version discrepancies.
Successful execution looks like: Successfully installed dipy-1.9.0 nibabel-5.2.1 nilearn-0.10.4 scikit-learn-1.4.1 ...

Command 4: Configure Mandatory Environment Variables

NeuroADHD enforces fail-closed cryptographic security to ensure synthetic session integrity:

export NEUROADHD_HMAC_KEY="neuroadhd_local_research_key_12345"

What it does: Sets the secret HMAC authentication key used to compute and verify SHA-256 integrity tokens for synthetic MRI sessions.
Successful execution looks like: The variable is loaded in memory silently. Verify by running echo $NEUROADHD_HMAC_KEY.

Command 5: Launch the Web Dashboard Server

PYTHONPATH=. .venv/bin/python scripts/serve_dashboard.py

What it does: Initializes the Python ThreadingHTTPServer on local port 8765, binds to 127.0.0.1, serves static frontend assets from frontend/, and establishes the REST API controllers.
Successful execution looks like:

Mode: STRICTLY_SYNTHETIC_ONLY | Real-data authorization: FALSE

STEP 5: What Happens Immediately After Upload? (Internal Workflow Sequence)

This section demystifies the exact 13-step technical chain reaction that occurs behind the scenes from the microsecond you click Upload until the results appear on screen.

5.1 The 13-Step Technical Sequence

  1. User Selects File: You choose session.zip in your browser using the HTML file input element.
  2. Frontend Pre-flight: frontend/app.js checks that a file is actually selected and validates that the file extension is .zip, .nii, .nii.gz, .json, or .pdf.
  3. Session Initialization Request: The frontend makes an HTTP POST /api/intake/sessions request with payload {"kind": "scan"}.
  4. Backend Session Allocation: src/intake/service.py:create_session() generates a timestamped session ID (e.g., session_20261107T150500_123456Z) and creates directory outputs/intake_sessions/<session_id>/.
  5. Streaming File Upload: The frontend streams raw binary file chunks using POST /api/intake/sessions/<session_id>/files with custom header X-Upload-Filename: session.zip.
  6. Memory-Safe Disk Streaming: In scripts/serve_dashboard.py, the server writes incoming bytes directly into outputs/intake_sessions/<session_id>/raw_uploads/session.zip using a 64 KB buffer, preventing server RAM exhaustion.
  7. Cryptographic Hash Verification: As the file is written, _sha256() computes the cryptographic SHA-256 checksum and saves it into the session manifest.
  8. Safe Archive Extraction: _extract_zip() inspects the archive for ZipSlip directory traversal attacks (ensuring no file extracts outside the target directory) and unpacks the contents into outputs/intake_sessions/<session_id>/bids_extracted/.
  9. Neuroimaging Header Inspection: _inspect_nifti() invokes nibabel.load() to parse the NIfTI headers:
    • Verifies the functional scan has 4 dimensions $(X, Y, Z, T)$ with $T \ge 50$ volumes.
    • Verifies the structural scan has 3 dimensions $(X, Y, Z)$ with $1\text{ mm}$ isotropic geometry.
    • Parses the companion JSON sidecar to confirm RepetitionTime is within $0.5\text{s} \le T_R \le 5.0\text{s}$.
  10. Session Manifest Persistence: An atomic JSON document (session_manifest.json) is written via a temporary file and atomic rename, recording all extracted file paths, dimensions, and checksums.
  11. Safety Gate Enforcement: The backend checks src/security/authorization.py:is_authorized(). Because clinical research credentials are not yet configured on this demo workspace, the backend tags the session as INTAKE_VALIDATED_AWAITING_RESEARCH_AUTHORIZATION and locks real-scan execution.
  12. Backend JSON Response: The server returns HTTP 200 OK with a JSON summary of the validated scans, volume count, and storage path.
  13. Frontend DOM Update: frontend/app.js renders a green confirmation box detailing the validated scans and updates the MRI uploads monitoring tab.

2. WHERE do I do it?

STEP 6: Complete 22-Stage Processing Pipeline

When a processing run is triggered (either automatically on synthetic data or manually via scripts/run_poc_v2.py), the computational engine executes exactly 22 chronological stages. Motion parameters are estimated on raw uncorrected BOLD (Stage 2) prior to slice-timing correction (Stage 3) and susceptibility distortion estimation (Stage 4), and all spatial transforms (rigid motion, optional B0 SDC displacement, EPI-to-T1w coregistration, T1w-to-MNI affine, and SyN warp) are composed in Stage 13 into a single spatial interpolation directly from the unresampled Stage 3 slice-time-corrected BOLD series.

Stage 1: BIDS Input & Sidecar Metadata Validation

  • Input: *_task-rest_bold.json sidecar, 4D BOLD NIfTI, 3D T1w NIfTI, and CC200 atlas file.
  • Processing: Validates $T_R$ within bounds, resting-state task name, minimum $T \ge 50$ volumes, optional volume censoring indices, and canonical/phantom CC200 atlas SHA-256 verification.
  • Output: Verified metadata dictionary and immutable input SHA-256 hashes (re-checked after Stages 2–4).
  • Next Stage →: Passes raw unresampled BOLD and validated metadata to Stage 2.

Stage 2: 3D Rigid Motion Parameter Estimation (Raw Uncorrected BOLD)

  • Input: Raw, uncorrected 4D BOLD volume series $(X \times Y \times Z \times T)$.
  • Processing: Uses src/preprocessing/motion.py:estimate_motion_parameters() (DIPY 6-DOF rigid alignment aligning volumes $t=1 \dots T-1$ to reference Volume 0). Computes Framewise Displacement ($FD$) using Power et al. (2012) ($r = 50\text{ mm}$): $$FD_t = |\Delta d_{x,t}| + |\Delta d_{y,t}| + |\Delta d_{z,t}| + 50 \cdot (|\Delta \alpha_t| + |\Delta \beta_t| + |\Delta \gamma_t|)$$
  • Output: rigid_motion_transforms, motion_parameters.tsv (6 cols), and framewise_displacement.tsv (1 col).
  • Next Stage →: Original raw BOLD continues unmodified to Stage 3.

Stage 3: Metadata-Driven Slice-Timing Correction (DEC-STC-01)

  • Input: Raw 4D BOLD on original slice geometry and BIDS SliceTiming / SliceEncodingDirection metadata (plus NIfTI header dim_info slice_dim).
  • Processing: Executed via src/preprocessing/slice_timing.py:write_slice_timing_derivative(). Temporally shifts each slice to reference_time (default $T_R/2$, logged as +TR/2 StartTime) using odd-point-reflected SciPy $C^2$ cubic spline interpolation (4-TR reflection padding, extrapolate=False). Never invents timings from $T_R$; validates explicit SliceEncodingDirection (i, i-, j, j-, k, k-) against NIfTI slice_dim, falling back to slice_dim (or skipping if undetermined) without assuming axis k.
  • Default Skip vs. Strict Mode: By default, missing SliceTiming or unknown slice axis logs a warning and emits a SKIPPED_* flag while preserving raw timings. With --strict-slice-timing, missing timings fail closed.
  • Output: derivatives/*_desc-stc_bold.nii.gz, derivatives/*_desc-stc_bold.json, and derivatives/*_desc-stc_report.json.
  • Next Stage →: Passes STC BOLD (or unmodified BOLD if skipped) to Stage 4.

Stage 4: B0 Susceptibility Distortion Correction (DEC-SDC-02)

  • Input: STC BOLD metadata/geometry and BIDS fmap/ directory (if present).
  • Processing: Executed via src/preprocessing/susceptibility_distortion.py:run_susceptibility_distortion_correction(). Discovers associated fieldmaps via BIDS rules (B0FieldSource/B0FieldIdentifier over IntendedFor; fails closed on ambiguity), validates PhaseEncodingDirection (i, i-, j, j-, k, k-) and TotalReadoutTime (or EffectiveEchoSpacing * (ReconMatrixPE - 1)), converts calibrated direct Hz / rad/s fieldmaps into PE pullback displacement_vox, and enforces Jacobian invertibility ($J(v) = 1 + \partial u_a / \partial v_a > 0$).
  • Default Skip vs. Strict Mode & Tool Limitation: By default, missing fieldmap, missing PhaseEncodingDirection, missing TotalReadoutTime, or missing FSL tools logs a SKIPPED_* flag (corrected = false). With --strict-sdc, any skip fails closed. Limitation: only direct Hz / rad/s fieldmaps are applied; FSL topup, prelude, and fugue were never run.
  • Output: Optional displacement_vox field and derivatives/*_desc-sdc_report.json (plus fieldmap/displacement/QC files when applied).
  • Next Stage →: Passes motion transforms, STC BOLD, and optional SDC displacement to Stage 5 and Stage 13.

Stage 5: Motion Transform (+ Optional SDC) Application

  • Input: Stage 3 STC BOLD, Stage 2 rigid_motion_transforms, and optional Stage 4 displacement_vox.
  • Processing: Applies rigid motion (+ optional SDC unwarping) via apply_motion_transforms() to form an aligned native series solely for Stage 6 functional reference estimation.
  • Output: Temporary aligned native BOLD (released after Stage 6).
  • Next Stage →: Passed to Stage 6.

Stage 6: 3D Functional Reference Generation

  • Input: Stage 5 motion-aligned (+ optionally unwarped) 4D native BOLD series.
  • Processing: Computes the voxel-wise temporal mean and brain mask to produce a high-contrast 3D EPI reference image.
  • Output: 3D EPI reference volume and EPI brain mask.
  • Next Stage →: Used as moving target for cross-modal coregistration in Stage 11.

Stage 7: Anatomical Brain Extraction

  • Input: Raw 3D T1-weighted anatomical scan.
  • Processing: Executes DIPY median_otsu segmentation followed by 3D binary morphological hole-filling.
  • Output: Clean brain-only parenchyma mask and skull-stripped T1w volume.
  • Next Stage →: Stripped anatomy passed to Stage 8.

Stage 8: Log-Polynomial Bias-Field Correction

  • Input: Skull-stripped T1w volume and brain mask.
  • Processing: Fits a 2nd-order 3D Legendre polynomial surface $B(x, y, z)$ to remove low-frequency $B_1$ intensity drift.
  • Output: Intensity-normalized anatomical image with uniform tissue contrast.
  • Next Stage →: Uniform anatomy passed to Stage 9.

Stage 9: Tissue Segmentation (CSF, GM, WM Probabilities)

  • Input: Bias-corrected T1w anatomical volume.
  • Processing: Fits a 3-component Gaussian Mixture Model (GMM) to estimate posterior probability maps for: Cerebrospinal Fluid (CSF), Cortical Grey Matter (GM), and Deep White Matter (WM).
  • Output: 3 probability arrays where $\sum_{k} p(C_k | v) = 1.0$.
  • Next Stage →: Probability maps passed to Stage 10.

Stage 10: Morphological Tissue Mask Erosion & Geometry Verification

  • Input: CSF and White Matter posterior probability maps.
  • Processing: Enforces $p \ge 0.96$ thresholding followed by 1-voxel inward 3D binary morphological erosion (6-connectivity) and zero-overlap verification.
  • Output: Clean, non-overlapping WM and CSF nuisance masks.
  • Next Stage →: Eroded masks passed to Stage 14.

Stage 11: EPI-to-T1w Rigid Coregistration

  • Input: 3D functional reference EPI (Stage 6) and T1w brain (Stage 7).
  • Processing: Optimizes a 6-DOF rigid transformation matrix using mutual information. When Stage 4 SDC was applied, evaluates distorted vs. unwarped EPI against coregistered T1w (correction_qc: ncc, nmi, mask_dice) and updates derivatives/*_desc-sdc_qc.png and *_desc-sdc_report.json.
  • Output: Coregistration affine matrix $R_{\text{EPI}\to\text{T1w}}$.
  • Next Stage →: Combined into Stage 13 single-step pullback.

Stage 12: T1w-to-MNI SyN Nonlinear Normalization

  • Input: Subject T1w anatomical brain and standard MNI152 stereotaxic template.
  • Processing: Computes a 12-DOF affine pre-alignment followed by DIPY Symmetric Normalization (SyN) diffeomorphic nonlinear warping onto MNI152 coordinates.
  • Output: Affine pre-alignment and nonlinear SyN deformation field.
  • Next Stage →: Combined into Stage 13 single-step pullback.

Stage 13: Composed Single-Step Pullback Resampling into CC200 Grid

  • Input: Unresampled Stage 3 STC 4D BOLD, Stage 2 motion transforms, optional Stage 4 SDC displacement, Stage 11 $R_{\text{EPI}\to\text{T1w}}$, Stage 12 SyN map, and CC200 atlas geometry.
  • Processing: Composes transforms via compose_transformations() (and compose_sdc_transform() when SDC active) and resamples STC BOLD directly onto the CC200 grid in ONE single spatial interpolation step via resample_4d_bold().
  • Output: Standard-space 4D BOLD series matching CC200 shape and affine.
  • Next Stage →: Standard-space BOLD passed to Stage 15 and Stage 18.

Stage 14: Tissue Mask Standard Grid Resampling

  • Input: Eroded CSF and WM masks (Stage 10) and Stage 12 SyN field.
  • Processing: Warps eroded tissue masks into standard CC200 space via nearest-neighbor interpolation (resample_mask_to_target()).
  • Output: Standard-space WM and CSF nuisance masks.
  • Next Stage →: Standard masks passed to Stage 15.

Stage 15: aCompCor Physiological Noise Extraction

  • Input: Standard-space 4D BOLD (Stage 13) and standard-space eroded WM/CSF masks (Stage 14).
  • Processing: Standardizes eroded WM/CSF timeseries and runs PCA to extract the top 5 aCompCor components.
  • Output: Array of 5 physiological noise regressors $(T \times 5)$.
  • Next Stage →: Components passed to Stage 17.

Stage 16: Friston-24 Motion Regressor Expansion

  • Input: 6 rigid realignment parameters estimated on raw BOLD in Stage 2 $(R_t)$.
  • Processing: Expands into the Friston-24 model $[R_t, R_{t-1}, R_t^2, R_{t-1}^2]$.
  • Output: Matrix of 24 motion regressors $(T \times 24)$.
  • Next Stage →: Motion regressors passed to Stage 17.

Stage 17: Confound Matrix Assembly & Collinearity Check

  • Input: 24 Friston regressors + 5 aCompCor components + linear trend + quadratic trend.
  • Processing: Assembles the full $T \times 31$ design matrix $X$, auditing rank ($31/31$) and SVD condition number. Global Signal Regression (GSR) and mean tissue regression remain explicitly OFF.
  • Output: confounds.tsv and confound_report.json.
  • Next Stage →: Confound matrix passed to Stage 18.

Stage 18: Simultaneous Nuisance Regression & Butterworth Bandpass

  • Input: Standard-space 4D BOLD and 31-column confound matrix $X$.
  • Processing: Applies simultaneous OLS nuisance projection and zero-phase Butterworth bandpass filtering via nilearn.image.clean_img() (order 5) retaining 0.01 Hz – 0.10 Hz: $$Y_{\text{clean}} = \left(I - X(X^T X)^{-1}X^T\right) Y$$
  • Output: Cleaned 4D BOLD volume series on standard CC200 grid.
  • Next Stage →: Cleaned functional data passed to Stage 19.

Stage 19: CC200 ROI Time Series Extraction

  • Input: Cleaned 4D BOLD series, Craddock CC200 atlas (200 parcels), and optional configured censor indices.
  • Processing: Uses src/parcellation/extractor.py:extract_cc200_timeseries() to compute spatial mean BOLD across each parcel ($i = 1 \dots 200$), producing $(200, T)$ in memory and roi_CC200.csv with 200 rows × $1 + T$ columns (node/volume + volumes 0..T-1).
  • Output: roi_CC200.csv.
  • Next Stage →: Timeseries passed to Stage 20.

Stage 20: Pairwise Fisher-$z$ Connectivity Vector Calculation

  • Input: 200 regional timeseries from Stage 19.
  • Processing: Computes pairwise Pearson correlations $r_{i,j}$ and Fisher's $z$-transformation ($z_{i,j} = \operatorname{arctanh}(r_{i,j})$), extracting the $19,900$ upper-triangular features.
  • Output: features_19900_fisher_z.csv and features_19900_fisher_z.npy.
  • Next Stage →: Features passed to Stage 21 (and optional frozen model inference).

Stage 21: Quality Control Visual Overlays

  • Input: Registered volumes, eroded masks, and CC200 parcellation.
  • Processing: Renders 4 core diagnostic PNG images (plus derivatives/*_desc-sdc_qc.png when Stage 4 SDC is applied):
    1. qc_registration_epi_to_t1w.png
    2. qc_registration_t1w_to_mni.png
    3. qc_tissue_masks.png
    4. qc_parcellation_cc200.png
  • Output: 4 core PNG overlays in the run directory.
  • Next Stage →: Passed to Stage 22.

Stage 22: Schema-Compliant Provenance JSON Generation

  • Input: All outputs, Stage 2–4 metadata/reports, software versions, memory metrics, and validation gates.
  • Processing: Writes provenance.json recording pipeline_stages_total: 22, preprocessing_order (22 stages), motion_estimation, slice_timing_correction, susceptibility_distortion_correction, validation_gates, output_artifacts, and SHA-256 output_checksums, validated against configs/provenance_schema.json.
  • Output: provenance.json, output_manifest.json, and run_manifest.json.
  • Final Result: Pipeline successfully completes.

6.2 Slice-Timing Correction (DEC-STC-01) & Susceptibility Distortion Correction (DEC-SDC-02)

Stage 3 (DEC-STC-01) and Stage 4 (DEC-SDC-02) operate after raw-BOLD motion estimation (Stage 2) and pass unresampled geometry/transforms into Stage 13 single-step pullback resampling:

  • Default Skip vs. Strict Behavior: Missing SliceTiming or unknown NIfTI slice_dim (when SliceEncodingDirection is absent) causes Stage 3 to log a warning and enter a SKIPPED_* status with a provenance flag rather than inventing timings from $T_R$. Missing associated fieldmaps (B0FieldSource/IntendedFor), missing PhaseEncodingDirection, missing TotalReadoutTime (when derivable fields are absent), or missing FSL binaries causes Stage 4 to log a SKIPPED_* flag (corrected = false) without fabricating warps. Passing --strict-slice-timing / --strict-sdc enforces fail-closed errors instead of skipping. Real-data mode must always use strict mode.
  • SDC Tool Limitation: Only calibrated direct (Hz / rad/s) fieldmaps are applied; FSL topup, prelude, and fugue were never installed or executed on live data (PEPOLAR and phase-difference paths report SKIPPED_TOOL_UNAVAILABLE by default).

12.3 Architectural Invariants & Guarantees

  • Fail-Closed Security: If an HMAC signature, NIfTI header, or JSON sidecar is malformed or invalid, execution halts immediately with zero partial state mutation.
  • Single-Step Resampling: Raw-BOLD rigid motion, optional B0 SDC displacement, coregistration, MNI affine prealignment, and SyN nonlinear spatial normalization are composed into one continuous mathematical pullback evaluated on unresampled STC BOLD, preserving high-frequency BOLD spectral power.
  • Zero Data Leakage: All standard scaling, imputation, and ANOVA feature selection transformations are computed strictly inside cross-validation splits.
  • Zero-Memory Disk Streaming: File uploads stream in 64 KB chunks directly to disk; server memory remains constant regardless of upload archive size.
