STEP 1: Project Introduction

1.1 What This Project Does

The NeuroADHD project is an automated neuroimaging preprocessing and feature extraction system. It ingests raw brain MRI scans (specifically 4D resting-state functional MRI scans and 3D anatomical structural scans), performs standardized medical image cleaning and spatial alignment, extracts regional neural signals from 200 distinct brain regions using the Craddock CC200 atlas, calculates pairwise functional connectivity (the strength of communication between brain regions), and feeds these connectivity values into a trained machine-learning model to predict ADHD-versus-neurotypical brain patterns for research.

1.2 Why This Project is Needed & The Problem it Solves

In historical research, machine-learning models were trained on pre-extracted tables of regional brain signals. However, raw MRI data coming directly from a hospital scanner (e.g., Siemens, GE, or Philips) cannot be fed into a machine-learning algorithm directly:

  • Head Motion: Patients naturally move their heads by fractions of a millimeter inside the scanner, corrupting functional measurements.
  • Anatomical Variation: Every human brain has a unique shape and size; brains must be mapped onto a standardized coordinate grid (the MNI152 template) so that region #45 in Patient A corresponds to region #45 in Patient B.
  • Physiological Noise: Heartbeats, breathing, and scanner magnetic field drifts create false signals that can drown out genuine neural activity.

The Solution: NeuroADHD provides an automated, standardized, reproducible 19-stage pipeline that handles raw scan intake, motion correction, skull stripping, tissue segmentation, spatial normalization, and nuisance regression, outputting standardized roi_CC200.csv tables and 19,900 Fisher-$z$ connectivity features without requiring manual neuroimaging software intervention.

1.3 Who Will Use It?

  • Neuroscience Researchers: Investigating functional brain connectivity alterations in neurodevelopmental conditions.
  • Biomedical Engineers & Data Scientists: Developing and validating computer-aided diagnostic algorithms.
  • Clinical Research Investigators: Evaluating prospective MRI cohorts in controlled academic studies.
IMPORTANT REGULATORY & MEDICAL DISCLAIMER
RESEARCH PROTOTYPE ONLY — NOT FOR CLINICAL DIAGNOSIS. ADHD is a psychiatric and behavioral neurodevelopmental condition diagnosed exclusively by certified clinicians through behavioral histories and DSM-5/ICD-11 criteria. This software must NEVER be used to diagnose, triage, or select treatments for patients. Real-scan preprocessing is locked behind a research authorization gate; all default runs execute in STRICTLY_SYNTHETIC_ONLY mode.

1.4 Plain-English Glossary of Technical Terms

TermSimple Plain-English Definition
fMRI (Functional MRI)An MRI technique that measures tiny blood-oxygen changes in the brain over time, showing which brain areas are active while a person rests.
BOLD Signal"Blood-Oxygen-Level-Dependent" signal. When neurons become active, they consume oxygen; BOLD measures this oxygen change.
T1-weighted MRI (T1w)A high-resolution, static 3D anatomical photograph of the brain's physical structure, showing sharp boundaries between grey and white matter.
VoxelA "3D pixel" inside an MRI scan. Just like a digital photo is made of 2D pixels, a 3D brain scan is made of millions of tiny cubes called voxels.
BIDS"Brain Imaging Data Structure" — a globally standardized folder and naming format used by neuroscientists to organize MRI files consistently.

Fisher z-TransformationA mathematical formula ($z = arctanh(r)$) that converts correlation values into normally distributed values suitable for machine learning.
FrontendThe user interface (webpage) you see in your browser with buttons, tables, and graphs.
BackendThe Python server running in the background that receives files, executes mathematics, and returns results.
API"Application Programming Interface" — the standardized communication bridge between the frontend and the backend.

Command 1: Navigate to the Project Root

cd "<your-project-folder>"

Where to execute: In your operating system Terminal.
What it does: Changes your active directory into the project root folder.
Successful execution looks like: Your terminal prompt displays the folder path without returning any error.

Command 2: Activate the Virtual Environment

source .venv/bin/activate

Where to execute: In the project root.
What it does: Activates the isolated Python virtual environment containing all pre-installed scientific packages (DIPY, Nilearn, NiBabel, Scikit-Learn, SciPy, NumPy, Pandas, Matplotlib).
Successful execution looks like: Your command line prompt is prefixed with (.venv).

Command 3: Install Pinned Dependencies (Fresh Setup Only)

If you are setting up on a completely new machine where .venv does not exist, create it and install pinned packages:

python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements-lock.txt

What it does: Installs the exact locked versions of the 35 required scientific libraries so that there are zero version discrepancies.
Successful execution looks like: Successfully installed dipy-1.9.0 nibabel-5.2.1 nilearn-0.10.4 scikit-learn-1.4.1 ...

Command 4: Configure Mandatory Environment Variables

NeuroADHD enforces fail-closed cryptographic security to ensure synthetic session integrity:

export NEUROADHD_HMAC_KEY="neuroadhd_local_research_key_12345"

What it does: Sets the secret HMAC authentication key used to compute and verify SHA-256 integrity tokens for synthetic MRI sessions.
Successful execution looks like: The variable is loaded in memory silently. Verify by running echo $NEUROADHD_HMAC_KEY.

Command 5: Launch the Web Dashboard Server

PYTHONPATH=. .venv/bin/python scripts/serve_dashboard.py

What it does: Initializes the Python ThreadingHTTPServer on local port 8765, binds to 127.0.0.1, serves static frontend assets from frontend/, and establishes the REST API controllers.
Successful execution looks like:

Mode: STRICTLY_SYNTHETIC_ONLY | Real-data authorization: FALSE

STEP 5: What Happens Immediately After Upload? (Internal Workflow Sequence)

This section demystifies the exact 13-step technical chain reaction that occurs behind the scenes from the microsecond you click Upload until the results appear on screen.

5.1 The 13-Step Technical Sequence

  1. User Selects File: You choose session.zip in your browser using the HTML file input element.
  2. Frontend Pre-flight: frontend/app.js checks that a file is actually selected and validates that the file extension is .zip, .nii, .nii.gz, .json, or .pdf.
  3. Session Initialization Request: The frontend makes an HTTP POST /api/intake/sessions request with payload {"kind": "scan"}.
  4. Backend Session Allocation: src/intake/service.py:create_session() generates a timestamped session ID (e.g., session_20261107T150500_123456Z) and creates directory outputs/intake_sessions/<session_id>/.
  5. Streaming File Upload: The frontend streams raw binary file chunks using POST /api/intake/sessions/<session_id>/files with custom header X-Upload-Filename: session.zip.
  6. Memory-Safe Disk Streaming: In scripts/serve_dashboard.py, the server writes incoming bytes directly into outputs/intake_sessions/<session_id>/raw_uploads/session.zip using a 64 KB buffer, preventing server RAM exhaustion.
  7. Cryptographic Hash Verification: As the file is written, _sha256() computes the cryptographic SHA-256 checksum and saves it into the session manifest.
  8. Safe Archive Extraction: _extract_zip() inspects the archive for ZipSlip directory traversal attacks (ensuring no file extracts outside the target directory) and unpacks the contents into outputs/intake_sessions/<session_id>/bids_extracted/.
  9. Neuroimaging Header Inspection: _inspect_nifti() invokes nibabel.load() to parse the NIfTI headers:
    • Verifies the functional scan has 4 dimensions $(X, Y, Z, T)$ with $T \ge 50$ volumes.
    • Verifies the structural scan has 3 dimensions $(X, Y, Z)$ with $1\text{ mm}$ isotropic geometry.
    • Parses the companion JSON sidecar to confirm RepetitionTime is within $0.5\text{s} \le T_R \le 5.0\text{s}$.
  10. Session Manifest Persistence: An atomic JSON document (session_manifest.json) is written via a temporary file and atomic rename, recording all extracted file paths, dimensions, and checksums.
  11. Safety Gate Enforcement: The backend checks src/security/authorization.py:is_authorized(). Because clinical research credentials are not yet configured on this demo workspace, the backend tags the session as INTAKE_VALIDATED_AWAITING_RESEARCH_AUTHORIZATION and locks real-scan execution.
  12. Backend JSON Response: The server returns HTTP 200 OK with a JSON summary of the validated scans, volume count, and storage path.
  13. Frontend DOM Update: frontend/app.js renders a green confirmation box detailing the validated scans and updates the MRI uploads monitoring tab.

STEP 6: Complete 19-Stage Processing Pipeline

When a processing run is triggered (either automatically on synthetic data or manually via the runner script), the computational engine executes exactly 19 chronological stages. Every stage is detailed below with its inputs, mathematical processing, outputs, storage paths, and handoff to the next stage.

Stage 1: BIDS Metadata & Schema Validation

  • Input: *_task-rest_bold.json sidecar and CC200 atlas file.
  • Processing: Validates $T_R = 2.000\text{ s}$, task name, and computes SHA-256 hash of the atlas against the authorized manifest.
  • Output: Verified metadata dictionary in Python memory.
  • Next Stage →: Passes verified scan geometry to Stage 2.

Stage 2: 4D BOLD Realignment & Motion Parameter Estimation

  • Input: Raw 4D BOLD volume series $(30 \times 30 \times 20 \times 60)$.
  • Processing: Uses DIPY AffineRegistration (Rigid-body, 6 Degrees of Freedom: $\Delta x, \Delta y, \Delta z, \text{rot}_x, \text{rot}_y, \text{rot}_z$) aligning every volume $t=1 \dots 59$ to reference Volume 0. Computes Framewise Displacement (FD): $$FD_t = |\Delta d_{x,t}| + |\Delta d_{y,t}| + |\Delta d_{z,t}| + |\Delta \alpha_t| + |\Delta \beta_t| + |\Delta \gamma_t|$$
  • Output: motion_parameters.tsv (6 cols) and framewise_displacement.tsv (1 col). Capped at $0.50\text{ mm}$ scrubbing threshold.
  • Next Stage →: Realigned 4D BOLD passed to Stage 3.

Stage 3: 3D Functional Reference Generation

  • Input: Realigned 4D BOLD volume series.
  • Processing: Computes the voxel-wise temporal mean across all motion-corrected volumes to produce a high-contrast 3D EPI reference image.
  • Output: 3D EPI reference image array $(30 \times 30 \times 20)$.
  • Next Stage →: Used as moving target for cross-modal coregistration in Stage 8.

Stage 4: T1w Skull Stripping & Brain Extraction

  • Input: Raw 3D T1-weighted anatomical scan $(32 \times 32 \times 24)$.
  • Processing: Executes DIPY median_otsu segmentation to peel away non-brain extra-cranial tissues (skull bone, marrow, scalp, dura mater) followed by 3D binary morphological hole-filling.
  • Output: Clean brain-only parenchyma mask and skull-stripped T1w volume (23,511 brain voxels).
  • Next Stage →: Stripped anatomy passed to Stage 5.

Stage 5: Anatomical Bias-Field Correction

  • Input: Skull-stripped T1w volume.
  • Processing: Fits a 2nd-order 3D Legendre polynomial surface $B(x, y, z)$ to estimate low-frequency $B_1$ magnetic field inhomogeneity drift and divides the intensity by the estimated field.
  • Output: Intensity-normalized anatomical image with uniform tissue contrast.
  • Next Stage →: Uniform anatomy passed to Stage 6.

Stage 6: 3-Class Tissue Segmentation (GMM)

  • Input: Bias-corrected T1w anatomical volume.
  • Processing: Fits a 3-component Gaussian Mixture Model (GMM) to estimate posterior probability maps for three distinct anatomical tissue classes: Cerebrospinal Fluid (CSF), Cortical Grey Matter (GM), and Deep White Matter (WM).
  • Output: 3 probability arrays $(32 \times 32 \times 24)$ where $\sum_{k} p(C_k | v) = 1.0$.
  • Next Stage →: Probability maps passed to Stage 7.

Stage 7: Strict Thresholding & 1-Voxel 3D Mask Erosion

  • Input: CSF and White Matter posterior probability maps.
  • Processing: Enforces a strict confidence threshold $p \ge 0.96$ to discard ambiguous boundary voxels, followed by a 1-voxel inward 3D binary morphological erosion using a 6-connectivity structuring element.
  • Output: Ultra-clean, non-overlapping WM and CSF masks (0 voxel boundary overlap) to prevent cortical neural signal bleeding into nuisance regressors.
  • Next Stage →: Eroded masks passed to Stage 11.

Stage 8: EPI-to-T1w Cross-Modal Coregistration

  • Input: 3D functional reference EPI (from Stage 3) and T1w brain (from Stage 4).
  • Processing: Optimizes a 6-DOF rigid transformation matrix using mutual information to align functional EPI space with high-resolution subject anatomical space.
  • Output: Coregistration affine matrix $R_{\text{EPI}\to\text{T1w}}$.
  • Next Stage →: Combined into composed pullback in Stage 10.

Stage 9: T1w-to-MNI152 SyN Diffeomorphic Nonlinear Registration

  • Input: Subject T1w anatomical brain and standard MNI152 stereotaxic template.
  • Processing: Calculates a 12-DOF affine pre-alignment followed by DIPY Symmetric Normalization (SyN) diffeomorphic nonlinear warping to map individual brain gyri onto standard MNI coordinates.
  • Output: Nonlinear deformation field $\Phi_{\text{T1w}\to\text{MNI}}$.
  • Next Stage →: Combined into composed pullback in Stage 10.

Stage 10: Single-Step Composed BOLD Resampling

  • Input: Raw motion-corrected 4D BOLD, rigid matrix $R_{\text{EPI}\to\text{T1w}}$, SyN warp $\Phi_{\text{T1w}\to\text{MNI}}$, and CC200 atlas geometry.
  • Processing: Composes transformations into one single pullback field: $$\mathcal{T}_{\text{composed}} = R_{\text{EPI}\to\text{T1w}} \circ \Phi_{\text{T1w}\to\text{MNI}}$$ Resamples functional BOLD data directly onto the CC200 $3\text{ mm}$ isotropic reference grid in ONE single interpolation step, completely eliminating multi-step interpolation blurring.
  • Output: Standard-space 4D BOLD series $(30 \times 30 \times 20 \times 60)$.
  • Next Stage →: Standard-space BOLD passed to Stage 15.

Stage 11: Resampling Eroded Tissue Masks into CC200 Space

  • Input: Eroded CSF and WM masks (from Stage 7) and SyN transformation field.
  • Processing: Warps the subject's eroded tissue masks into the standard CC200 template space.
  • Output: Standard-space nuisance masks (e.g., 31 WM voxels, 131 CSF voxels).
  • Next Stage →: Standard masks passed to Stage 12.

Stage 12: Physiological aCompCor Confound Extraction

  • Input: Standard-space 4D BOLD and eroded standard-space WM/CSF masks.
  • Processing: Extracts raw timeseries from voxels inside the eroded WM and CSF masks, standardizes them to unit variance, and computes Principal Component Analysis (PCA) to isolate the top 5 anatomical CompCor (aCompCor) components.
  • Output: Array of 5 physiological noise regressors $(60 \times 5)$.
  • Next Stage →: Components passed to Stage 14.

Stage 13: Friston-24 Autoregressive Motion Parameter Expansion

  • Input: 6 rigid realignment parameters from Stage 2 $(R_t)$.
  • Processing: Expands the 6 motion parameters into the complete Friston-24 model: $$[R_t, \quad R_{t-1}, \quad R_t^2, \quad R_{t-1}^2]$$ (6 current motions + 6 backwards temporal derivatives + 12 quadratic expansions).
  • Output: Matrix of 24 motion regressors $(60 \times 24)$.
  • Next Stage →: Motion regressors passed to Stage 14.

Stage 14: 31-Column Nuisance Confound Matrix Assembly

  • Input: 24 Friston regressors + 5 aCompCor components + linear trend + quadratic trend.
  • Processing: Assembles the full $60 \times 31$ design matrix $X$. Performs singular value decomposition (SVD) to audit matrix rank ($31/31$) and condition number. Global Signal Regression (GSR) and mean tissue regression remain explicitly OFF to preserve neurobiological correlation structures.
  • Output: confounds.tsv and confound_report.json.
  • Next Stage →: Confound matrix passed to Stage 15.

Stage 15: Simultaneous Regression & Butterworth Bandpass Filtering

  • Input: Standard-space 4D BOLD and 31-column confound matrix $X$.
  • Processing: Applies simultaneous Ordinary Least Squares (OLS) nuisance projection: $$Y_{\text{clean}} = \left(I - X(X^T X)^{-1}X^T\right) Y$$ combined with a 4th-order zero-phase Butterworth bandpass filter retaining resting-state frequencies between 0.01 Hz and 0.10 Hz.
  • Output: Fully cleaned 4D BOLD volume series $(30 \times 30 \times 20 \times 60)$.
  • Next Stage →: Cleaned functional data passed to Stage 16.

Stage 16: CC200 Atlas Parcellation & ROI Timeseries Extraction

  • Input: Cleaned 4D BOLD series and Craddock CC200 atlas (200 distinct regions).
  • Processing: For every region $i = 1 \dots 200$ and every volume $t = 1 \dots 60$, computes the spatial mean BOLD signal across all voxels belonging to parcel $i$: $$s_i(t) = \frac{1}{|V_i|} \sum_{v \in V_i} \text{BOLD}(v, t)$$
  • Output: roi_CC200.csv (exactly 200 rows $\times$ 60 timepoint columns + 1 node label column).
  • Next Stage →: Timeseries table passed to Stage 17.

Stage 17: Functional Connectivity & 19,900 Fisher-z Feature Extraction

  • Input: roi_CC200.csv (200 regional timeseries).
  • Processing: Calculates the pairwise Pearson correlation $r_{i,j}$ between all pairs of regions $(200 \times 200\text{ matrix})$. Applies Fisher's $z$-transformation: $$z_{i,j} = \operatorname{arctanh}(r_{i,j}) = \frac{1}{2} \ln\left(\frac{1 + r_{i,j}}{1 - r_{i,j}}\right)$$ Extracts the strictly upper-triangular unique elements (excluding diagonal self-correlations $r=1.0$ and mirrored duplicates): $$\text{Total Features} = \frac{200 \times 199}{2} = 19,900$$
  • Output: features_19900_fisher_z.csv and features_19900_fisher_z.npy.
  • Next Stage →: Features passed to Stage 18.

Stage 18: Quality Control (QC) Overlay Generation

  • Input: Slices from intermediate and final registered volumes.
  • Processing: Renders 4 high-resolution diagnostic images:
    1. qc_registration_epi_to_t1w.png: EPI contour overlaid on T1w anatomy.
    2. qc_registration_t1w_to_mni.png: MNI template contour overlaid on normalized T1w.
    3. qc_tissue_masks.png: CSF, Grey Matter, and White Matter masks.
    4. qc_parcellation_cc200.png: CC200 parcel boundaries overlaid on standard BOLD.
  • Output: 4 diagnostic PNG files saved in the run directory.
  • Next Stage →: Passed to Stage 19.

Stage 19: Provenance Audit Manifest & Schema Validation

  • Input: All generated files, system environment, software package versions, and runtime logs.
  • Processing: Computes SHA-256 hashes of all outputs, records peak memory and execution timestamps, and validates the resulting dictionary against the strict configs/provenance_schema.json schema.
  • Output: provenance.json, output_manifest.json, and run_manifest.json.
  • Final Result: Pipeline successfully completes.

STEP 11: Errors, Troubleshooting and Fixes

The table below lists every known issue, how to diagnose it from logs or terminal outputs, and the exact step-by-step remedy.

Symptom / Error Root Cause How to Identify Exact Solution
Address already in use: 8765 A previous instance of scripts/serve_dashboard.py is still running on port 8765. Terminal displays OSError: [Errno 48] Address already in use upon startup. Find and terminate the occupying PID:
lsof -ti:8765 | xargs kill -9
Then relaunch the server.
ModuleNotFoundError: No module named 'src' Python does not include the current working directory in its module search path. Script fails immediately on line 1 or 2 with import failure. Set the PYTHONPATH environment variable before python:
PYTHONPATH=. .venv/bin/python ...
RuntimeError: Mandatory HMAC integrity key not set Environment variable NEUROADHD_HMAC_KEY was not exported. Pipeline exits with fail-closed safety violation. Export a non-empty key string in your terminal session:
export NEUROADHD_HMAC_KEY="my_secret_key"
Cohort stuck in RUNNING A previous process was killed via Ctrl+C before updating the manifest. Dashboard runs table shows RUNNING indefinitely for an old date. Edit the manifest JSON file in outputs/dashboard_cohorts/<id>/cohort_manifest.json and set "status": "TERMINATED".
ZipSlip Security Exception Uploaded ZIP archive contains relative paths (e.g. ../../etc/passwd) attempting directory traversal. Intake validation fails with IntakeError: Archive contains illegal traversal path. Re-pack the ZIP cleanly using standard BIDS relative paths (e.g. sub-01/ses-1/...) without parent directory dot-dots.
BOLD Volumes < 50 Functional scan has fewer than 50 temporal timepoints ($T < 50$). Intake validator rejects scan with BOLD series must contain at least 50 volumes. Provide a valid resting-state fMRI acquisition session with sufficient temporal duration ($T \ge 50$).
RepetitionTime Out of Bounds JSON sidecar has $T_R < 0.5\text{s}$ or $T_R > 5.0\text{s}$ or missing parameter. Validator rejects with RepetitionTime out of acceptable scientific range. Ensure sub-*_task-rest_bold.json contains a valid numeric "RepetitionTime": 2.0.
Memory Guard Ceiling Exceeded Scan dimensions exceed resident set size budget (> 2.50 GB). Pipeline fails closed with MemoryGuardError: Memory ceiling exceeded. Verify that high-resolution scans are cropped or that system memory limit flag is adjusted appropriately.

12.3 Architectural Invariants & Guarantees

  • Fail-Closed Security: If an HMAC signature, NIfTI header, or JSON sidecar is malformed or invalid, execution halts immediately with zero partial state mutation.
  • Single-Step Resampling: Coregistration and SyN nonlinear spatial normalization are composed into one continuous mathematical pullback, preserving high-frequency BOLD spectral power.
  • Zero Data Leakage: All standard scaling, imputation, and ANOVA feature selection transformations are computed strictly inside cross-validation splits.
  • Zero-Memory Disk Streaming: File uploads stream in 64 KB chunks directly to disk; server memory remains constant regardless of upload archive size.
